# Code Review

## 审查维度

按优先级依次检查以下维度，发现严重问题立即报告，一般问题汇总后提出。

### 1. 正确性与健壮性 (Critical)

- **边界条件**: 数组越界、null/undefined 检查、空值处理
- **类型安全**: TypeScript 类型正确性、any 滥用
- **异步处理**: Promise/async-await 错误处理、竞态条件
- **状态管理**: React 状态更新方式、依赖数组完整性
- **表单验证**: 输入校验、错误提示

### 2. 安全性 (High)

- **XSS 防护**: `dangerouslySetInnerHTML` 使用、用户输入渲染
- **注入风险**: 动态 SQL、eval 使用、动态代码执行
- **敏感数据**: Token/密码硬编码、控制台日志泄露
- **权限控制**: 前端权限校验（补充后端验证）

### 3. 性能与优化 (Medium)

- **渲染性能**: 不必要的 re-render、key 使用、列表优化
- **内存泄漏**: 事件监听清理、定时器清理、订阅取消
- **代码分割**: 懒加载、动态导入
- **资源优化**: 图片压缩、包体积、tree-shaking
- **算法效率**: 循环嵌套、大数组操作、正则性能

### 4. 可读性与维护性 (Medium)

- **命名规范**: 变量/函数命名语义化、一致性
- **代码结构**: 文件组织、模块划分、关注点分离
- **注释质量**: 复杂逻辑注释、JSDoc 完整性
- **重复代码**: 可抽取的公共逻辑
- **魔法值**: 硬编码常量

### 5. ESLint 与代码风格 (Low)

- **Lint 规则**: ESLint 警告、可修复的格式问题
- **一致性**: 代码风格统一、import 顺序
- **最佳实践**: React Hooks 规则、未使用变量

### 6. 可访问性 (Bonus)

- **语义化 HTML**: 正确标签使用、aria 属性
- **键盘操作**: 焦点管理、快捷键支持
- **屏幕阅读器**: alt 文本、aria-label

### 7. 测试覆盖 (Bonus)

- **测试缺失**: 关键逻辑缺少测试
- **测试质量**: 边界条件测试、mock 合理性

## 审查策略

**核心原则：全面影响范围分析，不只审查修改行**

审查时需考虑变更的**上下文和影响范围**，从以下三个层面进行：

### 1. 修改行级别 (Line-level)
- 直接变更的代码行
- 变更的语法和逻辑正确性

### 2. 文件级别 (File-level)
- **整个文件的上下文** - 变更在文件中的作用
- **导入/导出一致性** - 新增/修改的导出是否在对应文件中被正确使用
- **文件内依赖** - 同文件中相关的函数/组件是否需要同步更新
- **类型定义** - 修改是否影响类型定义或接口

### 3. 项目级别 (Project-level)
- **跨文件影响** - 检查所有引用变更代码的文件
- **类型定义文件** - `.d.ts`、`interface.ts`、`types.ts` 等
- **共享组件** - 变更是否影响其他使用该组件的模块
- **配置文件** - `tsconfig.json`、`vite.config.ts`、`package.json` 等
- **测试文件** - 对应的 `.test.ts`、`.spec.ts` 是否需要更新
- **文档** - `README.md`、`CHANGELOG.md` 是否需要更新

## 审查流程

1. **理解变更目的** - 阅读描述，理解要解决的问题
2. **分析影响范围** - 确定需要检查的相关文件
3. **快速扫描** - 检查明显问题（语法、类型、安全）
4. **深度审查** - 按维度逐一检查修改部分和受影响区域
5. **输出报告** - 按严重程度分组：Critical > High > Medium > Low

## 影响范围分析

当审查变更时，分析以下问题来确定需要检查的相关文件：

### 代码变更类型 → 需要检查的文件

| 变更类型 | 需要检查的相关文件 |
|---------|------------------|
| 修改组件 Props | 所有使用该组件的文件、Storybook、类型定义 |
| 修改 API 接口 | API 调用方、类型定义文件、Mock 数据 |
| 修改状态管理 | 读取该状态的组件、相关 hooks、类型定义 |
| 修改工具函数 | 调用该函数的文件、单元测试 |
| 修改样式 | 依赖该样式的组件、CSS modules |
| 修改路由 | 导航配置、路由守卫、面包屑组件 |
| 新增功能 | 测试文件、文档、权限配置 |

```
**建议**: 修复建议或代码示例

---

### 相关文件中的问题

**建议**: 修复建议或代码示例

---

### 总结

- High: X 个
- Medium: X 个
- Low: X 个

备注: [需要注意的其他事项，如：需要在其他分支同步修改]
```
